# SynapseMail on hosting panels

Copyright (c) 2026 SynapseCyber.io · Developed by Milad Ahmadipour · CC BY-NC-ND 4.0

Generated by `tools/panel-docs.php` from the installer's help text. The web installer detects the hosting panel from the
install path and shows these steps next to each failed check ("How to fix on <panel>"). If the detection is wrong,
choose your panel at the top of the Environment step.

## How the panel is detected

| Panel | Install path |
|---|---|
| cPanel | `/home*/<user>/public_html/...` |
| Plesk | `/var/www/vhosts/<domain>/...` |
| DirectAdmin | `/home/<user>/domains/<domain>/public_html/...` |
| HestiaCP / VestaCP | `/home/<user>/web/<domain>/public_html/...` |
| CloudPanel | `/home/<user>/htdocs/<domain>/...` |
| aaPanel | `/www/wwwroot/<site>/...` |
| ISPConfig | `/var/www/clients/client<N>/web<N>/...` |
| Linux server (no panel) | `anything else` |

The web server (Apache, LiteSpeed, nginx) is read from the server signature, but the deciding test is the protection
probe: the installer writes a file to `db/` and tries to download it. If that works, `.htaccess` is ignored and the
install stays blocked until the folders are protected. See [TROUBLESHOOTING.md](TROUBLESHOOTING.md#nginx).

## cPanel

- **PHP 8.1 or newer:** cPanel → Software → Select PHP Version (or MultiPHP Manager): choose PHP 8.1 or newer for this domain.
- **Missing PHP extension (example: intl):** cPanel → Software → Select PHP Version → Extensions: tick intl. If you only have MultiPHP Manager, ask your host to enable intl.
- **Folder not writable (example: db/):** cPanel → File Manager: right-click db/ → Change Permissions → 755.
- **HTTPS:** cPanel → Security → SSL/TLS Status → Run AutoSSL, then Domains → turn on Force HTTPS Redirect.
- **db/ downloadable from the web (.htaccess ignored):** cPanel servers read .htaccess. File Manager → Settings → Show Hidden Files, check that .htaccess exists in the SynapseMail folder and in db/, config/, logs/ and temp/. If not, extract the zip again.
- **Finding the mail server:** cPanel → Email → Email Accounts → Connect Devices shows the mail server name and ports.

## Plesk

- **PHP 8.1 or newer:** Plesk → Websites & Domains → your domain → PHP: choose PHP 8.1 or newer (FPM served by Apache or nginx).
- **Missing PHP extension (example: intl):** Plesk → Tools & Settings → PHP Settings → your PHP version: enable intl (server admin), or ask your host.
- **Folder not writable (example: db/):** Plesk → Files: select db/ → Change Permissions: give the owner read, write and execute.
- **HTTPS:** Plesk → Websites & Domains → SSL/TLS Certificates → install a free Let's Encrypt certificate and turn on "Redirect from HTTP to HTTPS".
- **db/ downloadable from the web (.htaccess ignored):** Plesk with "nginx only" ignores .htaccess. Websites & Domains → Apache & nginx Settings: enable Apache (proxy mode), or paste the nginx rules below into "Additional nginx directives".
- **Finding the mail server:** Plesk → Mail → Mail Settings shows the mail server; it is usually your domain name or the server host name.

## DirectAdmin

- **PHP 8.1 or newer:** DirectAdmin → Extra Features → Select PHP Version (or Domain Setup → PHP version): choose 8.1 or newer.
- **Missing PHP extension (example: intl):** DirectAdmin → Select PHP Version → Extensions: tick intl. Server admins: CustomBuild → PHP extensions.
- **Folder not writable (example: db/):** DirectAdmin → File Manager: select db/ → Set Permission → 755.
- **HTTPS:** DirectAdmin → Account Manager → SSL Certificates → free certificate from Let's Encrypt, then tick "Force SSL with https redirect".
- **db/ downloadable from the web (.htaccess ignored):** DirectAdmin runs Apache or LiteSpeed by default and reads .htaccess. On an nginx-only server, the admin adds the nginx rules below under Custom HTTPD Configurations.
- **Finding the mail server:** DirectAdmin → E-Mail Manager → E-Mail Accounts: the server is usually mail.<your domain>.

## HestiaCP / VestaCP

- **PHP 8.1 or newer:** Hestia → Web → edit the domain → Advanced Options → Backend Template: choose PHP 8.1 or newer.
- **Missing PHP extension (example: intl):** Server admin (SSH, root): Debian/Ubuntu `apt install php8.3-intl`, RHEL/Alma/Rocky `dnf install php-intl`, then restart PHP-FPM or Apache.
- **Folder not writable (example: db/):** Over SSH: `chmod 755 db/` inside the SynapseMail folder, and make sure the folder belongs to the account that runs PHP.
- **HTTPS:** Hestia → Web → edit the domain → Enable SSL → Use Let's Encrypt, and tick "Enable automatic HTTPS redirection".
- **db/ downloadable from the web (.htaccess ignored):** Hestia's default nginx + Apache setup reads .htaccess. With an nginx-only (php-fpm) proxy template it does not: switch the Proxy Template back to "default" with Apache, or add the nginx rules below to a custom template.
- **Finding the mail server:** Hestia → Mail: the server is usually mail.<your domain>.

## CloudPanel

- **PHP 8.1 or newer:** CloudPanel → Sites → your site → Settings → PHP Version: choose 8.1 or newer.
- **Missing PHP extension (example: intl):** Server admin (SSH, root): Debian/Ubuntu `apt install php8.3-intl`, RHEL/Alma/Rocky `dnf install php-intl`, then restart PHP-FPM or Apache.
- **Folder not writable (example: db/):** Over SSH: `chmod 755 db/` inside the SynapseMail folder, and make sure the folder belongs to the account that runs PHP.
- **HTTPS:** CloudPanel → Sites → your site → SSL/TLS → Actions → New Let's Encrypt Certificate.
- **db/ downloadable from the web (.htaccess ignored):** CloudPanel uses nginx only, so .htaccess is ignored. Sites → your site → Vhost: add the nginx rules below inside the server block and save.
- **Finding the mail server:** CloudPanel has no mail server: use the IMAP and SMTP host of your mail provider.

## aaPanel

- **PHP 8.1 or newer:** aaPanel → Website → your site → PHP Version: choose 8.1 or newer.
- **Missing PHP extension (example: intl):** aaPanel → App Store → your PHP version → Setting → Install extensions: install intl.
- **Folder not writable (example: db/):** aaPanel → Files: db/ → Permission 755, owner www.
- **HTTPS:** aaPanel → Website → your site → SSL → Let's Encrypt, then turn on Force HTTPS.
- **db/ downloadable from the web (.htaccess ignored):** aaPanel uses nginx by default, so .htaccess is ignored. Website → your site → Config: add the nginx rules below and save.
- **Finding the mail server:** Use the host of the aaPanel Mail Server plugin or of your mail provider.

## ISPConfig

- **PHP 8.1 or newer:** ISPConfig → Sites → Website → PHP Version: choose 8.1 or newer (PHP-FPM).
- **Missing PHP extension (example: intl):** Server admin (SSH, root): Debian/Ubuntu `apt install php8.3-intl`, RHEL/Alma/Rocky `dnf install php-intl`, then restart PHP-FPM or Apache.
- **Folder not writable (example: db/):** Over SSH: `chmod 755 db/` inside the SynapseMail folder, and make sure the folder belongs to the account that runs PHP.
- **HTTPS:** ISPConfig → Sites → Website: tick SSL and Let's Encrypt SSL, then save.
- **db/ downloadable from the web (.htaccess ignored):** On an nginx server, ISPConfig → Sites → Website → Options → nginx Directives: add the nginx rules below.
- **Finding the mail server:** ISPConfig → Email → Domain: the server is usually the host name of the mail server.

## Linux server (no panel)

- **PHP 8.1 or newer:** Debian/Ubuntu: `apt install php8.3 php8.3-fpm` (or newer). RHEL/Alma/Rocky: `dnf module enable php:8.2 && dnf install php php-fpm`.
- **Missing PHP extension (example: intl):** Server admin (SSH, root): Debian/Ubuntu `apt install php8.3-intl`, RHEL/Alma/Rocky `dnf install php-intl`, then restart PHP-FPM or Apache.
- **Folder not writable (example: db/):** `chown -R www-data: config db logs temp` (Debian/Ubuntu; `apache:` on RHEL) and `chmod 755 db/`.
- **HTTPS:** Install certbot and run `certbot --apache -d your-domain` (or `--nginx`).
- **db/ downloadable from the web (.htaccess ignored):** Apache: `a2enmod rewrite` and `AllowOverride All` for the SynapseMail folder, then reload Apache. nginx: Add the nginx rules shown below.
- **Finding the mail server:** Check that the mail server accepts connections on 993, 465 or 587 from this server, e.g. `nc -vz mail.example.com 993`, and open those ports in the firewall.
